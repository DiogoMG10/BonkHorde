## The model

- GitHub is the source of truth. Each developer has their own checkout, their own local `.rbxl`
  file and their own `rojo serve`. Nobody shares a sync session.
- `default.project.json` is the one Rojo project. It is locked to unpublished local files
  (`servePlaceIds: [0]`) and blocks the live place (`blockedPlaceIds`). Rojo is never connected
  to the shared Team Create place.
- The Studio MCP runs Play tests, reads Output, takes screenshots, inspects, and stages work in
  `Workspace.Staging`. It never edits anything Rojo manages.
- The shared Team Create place is a release target. Nobody develops in it.

## What Rojo manages, and what it leaves alone

Managed (Rojo replaces these on every sync; never edit them in Studio):

| Instance | Source on disk |
|---|---|
| `ReplicatedStorage.Packages` | `Packages/` (run `wally install`) |
| `ReplicatedStorage.Shared` | `src/shared` |
| `ReplicatedStorage.Assets` | `assets/models/Assets.rbxmx` |
| `ServerScriptService.Server` | `src/server` |
| `StarterPlayer.StarterPlayerScripts.Client` | `src/client` |
| `StarterGui` (all of it) | `src/ui` (generated by the UI builder: edit the spec, not the JSON) |
| Declared settings | `$properties` in `default.project.json` (Workspace streaming and signals, StarterPlayer, Lighting.Technology = ShadowMap, StarterGui.ScreenOrientation) |

Left alone (lives only in the place file): `Workspace.Staging`, Terrain and Camera,
`ServerStorage` helpers, Lighting children (rebuilt at runtime by MapService anyway),
TextChatService and AvatarSettings configuration, `HttpService.HttpEnabled`, and every
experience setting stored on the Roblox website (permissions, collaborators, monetisation).

## Checking a place against disk

```powershell
# needs Lune 0.10+ (the repo's pinned 0.8.9 cannot read Studio's compressed place files)
& "$env:USERPROFILE\.rokit\tool-storage\lune-org\lune\0.10.5\lune.exe" run tools/rojo/drift.luau <place.rbxl>
```

It reports managed trees and declared settings as `same` or `DRIFT`, and lists the unmanaged
objects. In Studio, `tools/rojo/fingerprint.luau` (paste into the command bar) prints the same
picture for an open place, plus its PlaceId and GameId. Settings the command bar cannot read
(`SignalBehavior`, `StreamingIntegrityMode`, `Lighting.Technology`) print `UNREADABLE`; only the
drift check above covers them.

## Migration test in a disposable copy (steps 3 and 4)

1. Make a fresh backup of the shared place and copy it to a disposable file (never open the
   backup itself for testing).
2. Open the disposable copy. Paste `tools/rojo/fingerprint.luau`: note `PlaceId` and `GameId`.
3. **Lock test first:** `rojo serve tools/rojo/locktest.project.json` (port 34874). In the Rojo
   plugin set port 34874 and Connect. **Pass: the plugin refuses** (place not allowed). If it
   connects, a `ReplicatedStorage.RojoLockTest` appears: disconnect, stop, report.
4. **Valid sync:** `rojo serve` (default project, port 34872). Plugin on port 34872, Connect.
   If a confirmation list appears, it may only list managed instances. Accept.
5. Paste the fingerprint again: UNMANAGED lines identical, SETTINGS identical.
6. Play: Output shows the expected `BUILD` stamp. Stop. Disconnect. Close without saving.

## Daily workflow (after the checkpoints pass)

1. `git pull`, `wally install` if `wally.lock` changed.
2. Open your local `DEV-<name>.rbxl`, run `rojo serve`, click Connect in the plugin.
3. Edit on disk. Before each Play test run the gates and check the build stamp in Output.
   Gates: `python check.py` (from the roblox-code skill) or the four commands in the README
   (`rojo build -o <tmp>.rbxl`, `lune run test`, `selene src`, `stylua --check src lune`).
4. Work built in Studio goes in `Workspace.Staging`, then is exported to disk (see Assets).
5. Commit, push your branch, open a PR. Disconnect when you close Studio.

## Setting up a developer machine

Once per developer, on their own computer. Nothing here needs another developer's files: the
backups in `D:\Dev.2\BonkHorde-backups` exist only on Diogo's machine and are not required.

1. Install Git, Roblox Studio and Rokit (or Aftman). Clone the repo, then in it run
   `rokit install` (reads `aftman.toml`: Rojo 7.7.1, Wally, Selene, StyLua, Lune) and
   `rojo plugin install` (installs the Studio plugin matching the CLI). Restart Studio.
2. `git checkout main`, `git pull`, `wally install`. Run the gates: all green.
3. Make your own place file `DEV-<name>.rbxl`, **outside the repo**. Either:
   - **From the live place** (needs edit access to it): open it in Studio, **File → Save to
     File As** → `DEV-<name>.rbxl`, close the live place without changing anything, then open
     the saved file. Do not connect Rojo while the live place is open (it is blocked anyway).
   - **From disk only:** `rojo build -o DEV-<name>.rbxl`. It has every managed tree and the
     declared settings but none of the unmanaged objects (no `Workspace.Staging`, no Lighting
     effects until MapService builds them, default TextChatService and `HttpEnabled`).
     *Not yet tested as a daily place:* Play it once and report what is missing.
4. Open `DEV-<name>.rbxl` and paste `tools/rojo/fingerprint.luau`. **It must say
   `PlaceId=0 GameId=0`.** Otherwise Rojo will refuse it; do not loosen the lock, use the
   from-disk option instead.
5. `rojo serve` (port 34872). Plugin on port 34872, Connect, accept (the list may only show
   managed instances).
6. Play: Output shows `BUILD <stamp>` equal to `BuildStamp` in
   `src/shared/Config/GameConfig.luau`. Stop. Save `DEV-<name>.rbxl`: it is yours.

Each developer runs their own `rojo serve` against their own file; nobody connects to someone
else's session, and the port only has to be free on your own machine.

## Releasing to the shared place (draft, NOT rehearsed)

Must be rehearsed on a private staging place before production. Rojo is never connected to
the live place; the release file is prepared locally and published.

1. Tag the release on `main` (gates green, build stamp bumped).
2. In Studio, open the live place, **File → Save to File As** → `releases/<tag>-base.rbxl`
   (outside the repo). This is also the rollback copy.
3. Open that file. Paste the fingerprint and check its `PlaceId`:
   - `PlaceId = 0`: `rojo serve` at the tag, Connect, accept, disconnect.
   - `PlaceId ≠ 0`: Rojo refuses by design; do not loosen the lock. Use the fallback below.
4. Run the drift check on the saved release file: verdict `NO DRIFT`.
5. Playtest locally, then publish to the staging place, then (later, once rehearsed) to the live
   place. Roblox keeps version history: rollback is "restore previous version", or republish the
   base file.

Fallback if local copies keep the live PlaceId: build the release file from disk
(`rojo build -o release.rbxl`; the project now carries the place settings), carry over the
unmanaged configuration listed above, check it with the drift tool, and publish.

## Assets: where sources live and how they are preserved

| Asset | Source of truth | Only on Roblox |
|---|---|---|
| 51 generated meshes (heroes, enemies, props, pickups, weapons) | Ids, sizes and triangle counts in `assets/meshes/manifest.json`; prompts in `design/meshes.json`; instances in `Assets.rbxmx` | **Geometry and textures** |
| UI images and icons | PNG sources in `assets/ui/icons`, ids in `src/ui` | Uploaded copies only |
| VFX textures | PNG sources in `assets/vfx/tex` | Uploaded copies only |
| Sounds | Creator Store ids in `src/shared/Sounds.model.json` and `SoundBank` | Not ours to keep; ids only |
| `Workspace.Staging` | A copy of the same 51 models (no unique meshes as of the 2026-10-13 backup) | Nothing unique |

Rules: the repo keeps references and recipes, not large binaries. New Studio-made models are
built in `Workspace.Staging`, exported to `assets/models/<Category>/<Name>.rbxmx` and then
referenced by the project. Mesh and image content must be saved to Roblox (a permanent asset
id) before it is committed; session-only Editable content is lost on save. Dated place backups
live outside the repo in `D:\Dev.2\BonkHorde-backups` (Diogo's machine only). A one-time archive export of the 51
meshes (Studio "Export Selection") to that folder is recommended but not required.
